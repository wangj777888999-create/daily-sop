## 1. 整体布局

页面采用「学校工作台」模式，分为左侧学校列表和右侧工作台两个区域。

```
┌─────────────────────────────────────────────────────┐
│ 左侧栏 (180px)        │  学校工作台                  │
│                       │  ┌─────────────────────────┐ │
│  [+ 新建学校]         │  │ Tab: 内容素材 | 数据图表  │ │
│  ─────────────        │  └─────────────────────────┘ │
│  ○ 朝阳校区           │                              │
│  ● 海淀校区  ← 选中   │  （Tab 内容区）               │
│  ○ 西城校区           │                              │
└─────────────────────────────────────────────────────┘
```

**左侧学校列表：**
- 本地 JSON 存储，每学期手动维护
- `[+ 新建学校]` 按钮：弹窗从数据库查询 `gs_school` 表，下拉选择后确认创建
- 学校条目 hover 时显示删除按钮（仅删除本地记录，不影响数据库）
- 未选中任何学校时，右侧显示空状态引导提示

**右侧工作台：**
- 完全跟随左侧选中的学校上下文
- 顶部两个 Tab：**内容素材** 和 **数据图表**

## 2. 内容素材 Tab

```
┌──────────────────────────────────────────────────────────┐
│ 板块列表 (200px)      │  编辑区                          │
│                       │                                  │
│  [+ 新建板块]         │  标题：[可编辑]                   │
│  ─────────────        │                                  │
│  ▶ 学校概况           │  正文内容（多行文本）              │
│  ● 课程开展情况 ←选中 │                                  │
│  ▶ 活动记录           │  ──── 图片 ────                  │
│  ▶ 教练团队           │  ┌──┐ ┌──┐ ┌──┐                 │
│                       │  │图│ │图│ │ + │← 点击上传       │
│                       │  └──┘ └──┘ └──┘                 │
└──────────────────────────────────────────────────────────┘
```

### 板块（Section）
- 每个学校下可创建多个板块，每个板块包含：`标题 + 正文文本 + 图片列表`
- 支持重命名、删除（hover 显示操作按钮）
- 支持拖拽排序

### 编辑区
- 标题和正文均为可直接编辑的文本
- **自动保存**：输入停顿 1 秒后静默保存，无需手动点击
- 图片区域：缩略图网格，点击 `+` 上传，点击图片放大预览，hover 显示删除按钮

## 3. 数据图表 Tab

图表部分当前为**占位框架**，待 SQL 查询确定后单独迭代完善。

预留 4 个图表卡片槽位：
| 位置 | 图表名称 | 图表类型 | 状态 |
|------|----------|----------|------|
| 左上 | 性别分布 | 饼图 | 待定 SQL |
| 右上 | 月度上课人次 | 柱状图 | 待定 SQL |
| 左下 | 月度到课率 | 折线图 | 待定 SQL |
| 右下 | 教练上课情况 | 横向柱状图 | 待定 SQL |

**已确认的设计决策：**
- 所有图表共用同一套 SQL 模板，以 `school_name` 为参数过滤
- 复用现有 `databaseApi.query()` 接口执行查询
- 顶部提供时间范围筛选，所有图表联动刷新
- 每张图表提供「截图」按钮，导出为 PNG 供报告使用
- 图表库：**ECharts**（新增依赖 `echarts` + `vue-echarts`）

## 4. 数据存储

### 前端本地状态
无持久化前端状态，全部由后端 API 管理。

### 后端文件存储
```
data/
└── campus_reports/
    ├── index.json                          # 学校列表
    │   └── [{id, name, created_at}]
    └── {school_id}/
        ├── images/                         # 上传的图片文件
        │   └── {filename}
        └── {section_id}.json               # 板块内容
            └── {id, title, content, images[], order, created_at, updated_at}
```

## 5. 后端 API（新增路由）

挂载路径：`/api/campus-reports`，新建 `backend/api/campus_report_routes.py`。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/schools` | 获取学校列表 |
| POST | `/schools` | 新建学校 `{name}` |
| DELETE | `/schools/{school_id}` | 删除学校及其所有数据 |
| GET | `/schools/{school_id}/sections` | 获取板块列表（含内容） |
| POST | `/schools/{school_id}/sections` | 新建板块 |
| PUT | `/schools/{school_id}/sections/{section_id}` | 更新板块（标题/正文/顺序） |
| DELETE | `/schools/{school_id}/sections/{section_id}` | 删除板块 |
| POST | `/schools/{school_id}/images` | 上传图片（multipart） |
| DELETE | `/schools/{school_id}/images/{filename}` | 删除图片 |
| GET | `/schools/{school_id}/images/{filename}` | 访问图片文件 |
